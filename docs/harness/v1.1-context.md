# Harness v1.1 — Context for Future Agents

> **Superseded in part by v1.2** — see `docs/harness/v1.2-context.md`. The six invariants below all
> still hold, and the planning pipeline is unchanged. But the "Final review" contract described in
> `spec-lead` (two 0–10 scores, both ≥9 → recommend approval) took **no measured input**, and v1.2
> replaced that input: scores are now derived, `min(gate_cap, judgement)`. Do not restore the
> unmeasured form.

Read this before changing the planning/execution flow, the session skills, or
`spec-lead`. It captures what v1 did, what v1.1 changed, why, and the invariants you
must not break.

## TL;DR

v1.1 replaced the slow, in-place-mutated `/shape-spec` plan document with a **fixed
planning pipeline** whose output is a set of **tracer-bullet tickets** (= the lane
table). Plans are now leaner, parallelizable, and don't rot across sessions. The
execution side (parallel scheduler, PREVC lifecycle) was already good and is unchanged.

## v1 (old) — how plans were made

- `/shape-spec` (Agent OS) produced one heavy `plan.md` (+ shape/standards/evals/
  references) up front. Real examples reached **400–611 lines**.
- Tasks were **coarse, horizontal, serialized** (`Task 1 → 2 → … → 9`). No blocking
  DAG, no per-task file ownership.
- Revisions were **patched into `plan.md` in place** → the doc accreted contradictory
  layers ("Part I — Current Authority" vs "Part II — Original Plan History",
  "Superseded by lanes R1–R6"). Every session paid a tax re-reading the doc and
  reconciling "which part wins" → slow + slop + risk of following superseded wording.

## v1.1 (current) — the planning pipeline

`spec-lead` Planning role is a fixed pipeline (also exposed as `/plan`):

```
0. SIZE-GATE  -> wayfinder     (large/foggy/cross-subsystem only; else skip)
1. SHARPEN    -> grill-with-docs in AUTO mode
                 (self-resolves, labels Decisions vs Assumptions, writes ADRs;
                  escalates only on a real blocker)
2. DECOMPOSE  -> to-tickets = the LANE TABLE
                 (tracer-bullet vertical slices, one file per ticket, blocking edges)
   -> PREVC awaiting_plan_approval (single gate)
```

Then `spec-lead` becomes the **scheduler** (unchanged from before v1.1): dispatches
independent lanes in parallel via `task(background:true)`, polls status, reconciles,
and creates **one local commit**. Each lane runs the `implement` discipline
(TDD → typecheck → tests → code review), **without committing**.

### Where plans live (tracker convention)

Local markdown, no external tracker. See `docs/harness/matt-pocock-tracker.md`.

```
agent-os/specs/<YYYY-MM-DD-HHMM-slug>/
  plan.md            # lean: objective, scope, non-goals, AUTO decisions/assumptions, AC
  tickets/           # THE canonical task list — one file per ticket = one lane
    00-map.md        # wayfinder map (large efforts only)
    NN-<slug>.md     # What to build, Blocked by, Owner capability, file ownership, verify
```

The `tickets/` set **is** the task list and the lane table. Revisions = **close a
ticket + open a new one**, never patch a monolithic doc. That is the core slop fix.

## Invariants — do NOT break these

1. **One write-capable lane owns a file at a time.** Tickets with intersecting file
   ownership are not independent — serialize or merge.
2. **Only the scheduler commits.** Implementers edit; they never commit → parallel
   lanes never race on git. (`implement` skill enforces "dispatched → do not commit".)
3. **`spec-lead` edit rule (single-session):** may write plan artifacts and edit source
   **sequentially**; **never edits while parallel specialists are in flight**.
4. **Single approval gate.** `to-tickets`'s quiz and AUTO grilling fold into PREVC's
   one `awaiting_plan_approval` stop. An autonomous run ("execute all tasks in plan X")
   IS the authorization and skips per-task prompts.
5. **Never automatic:** push, deploy, branch create/change, worktree, remote git.
6. PREVC owns lifecycle state. Session/handoff skills do not write passing/blocked.

## Model tiers (opencode.jsonc, at time of writing — verify before relying)

Cost-lean split (GPT Pro basic plan): only the **scheduler** (`spec-lead`) runs a paid
model — `gpt-5.6-sol` at variant `medium`. **Every other agent (all 18)** runs
`opencode-go/deepseek-v4-flash` at variant `max` — reviewers, advisors, planners,
`design-director`, `security-analyst`, every language/stack engineer, `test-automation-engineer`,
`fixer`, and `explorer`. `max` is a valid effort for this model (models.dev lists its
efforts as `low`/`high`/`max`; note `xhigh` is NOT valid for the opencode-go deepseek
lane). Earlier revisions kept the "thinking" roles on `gpt-5.6-luna xhigh`; that was
consolidated so only `spec-lead` is paid. Trade-off: the review/advisory gate quality is
now bounded by deepseek — an explicit cost decision.

## Background dispatch: the stub-is-not-a-result rule + serial fallback

Parallel dispatch (`start-parallel.ps1` → `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS` +
`OPENCODE_EXPERIMENTAL_PARALLEL`) has a sharp edge. `task(background: true)` returns
**immediately** with a stub — `<task state="running">Background task started. You will be
notified… DO NOT poll or duplicate…</task>`. That stub carries **no result, edits, or
evidence**. If the scheduler treats it as the outcome, it wrongly concludes "returned without
edits/evidence" and re-dispatches a **still-running** lane — duplicating work and racing files —
while the child actually finishes fine (verified in `opencode.db`: children ended `finish:stop`
with full reports; the `spec-lead` task parts held the 98/474-char stub, not the report).

Two mitigations, both shipped:
1. **`agent/spec-lead.md` hardened** — explicit rule: the stub is not a result; never reroute,
   duplicate, or judge a lane whose `task_status` is still `running`; reconcile only after a
   **terminal** state, having read the child's final report.
2. **`scripts/start-serial.ps1`** — launches opencode with the experimental flags OFF, so
   `task()` **blocks** and returns the child's real report directly. No race. Reliable default;
   trade-off is no parallelism. Use it when background dispatch misbehaves.

Aggravator worth knowing: a slow subagent effort (e.g. `deepseek-v4-flash` at `max`, ~4–5 min/lane)
**widens** the window where only the stub exists, so the race fires far more often — it looks
like "the model change broke dispatch" when the real bug is the stub handling.

## Base autonomous-run prompt

```
Execute all tasks in plan <spec-path> under PREVC as an autonomous run.
Use the plan's declared lanes as the lane table (tickets/ if present) — do not re-plan;
otherwise propose a lane table per phase.
Parallelize independent lanes, serialize lanes sharing a file, one writer per file.
Use recommended subagents.
When all tasks land, run @code-reviewer and @architecture-reviewer in parallel over the
diff. Stop at awaiting_confirmation.
```

## Gotchas / honest caveats

- **AUTO grilling can bake a wrong assumption silently.** It labels them under
  "AUTO Decisions And Assumptions" in `plan.md` — an operator MUST skim those at the
  gate (that skim IS the plan-approval an autonomous run otherwise skips).
- **Ticket sizing quality matters.** A too-fat ticket (many files, several concerns)
  re-introduces intra-lane drift. Prefer splitting when ownership or concern diverges.
- **Complex production work has inherent length** — v1.1 removes accidental slop, not
  essential complexity.
- **The public docs site is a SEPARATE repo** (`opencode-harness-guide`, unrelated
  history, curated subset) deployed via its own `deploy-docs.yml`. This repo's origin
  is `opencode`. Update the site by pushing to the guide repo's own history, not by
  force-pushing this one.
